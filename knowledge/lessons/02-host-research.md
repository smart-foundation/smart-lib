# 02 — Host research lessons (Wave 1, Agent B)

Appended by the host-capability researcher. Process lessons only — the map itself is `02-HOST-CAPABILITIES.md`.

1. **Probe, don't assume.** Every Linux claim in the report is marked [V] only because a probe ran (`/tmp/kilo/syscall_probe*.py`, since deleted). The surprises found only by probing: `O_TMPFILE` returns EINVAL on this box; `fanotify_init` returns EPERM for seven flag combos (only bare `FAN_REPORT_FID` succeeds); `pidfd_getfd` works for descendants despite Yama=1; memfd seals work but only with `MFD_ALLOW_SEALING` at creation. Any one of these would have been wrong in a knowledge-only report.
2. **A forgotten `ctypes` detail produced two false readings.** Passing Python ints where the kernel expects pointers gave `EFAULT` for `statx(buf=NULL)` and `io_uring_setup(params=NULL)` — the *dispatched* code returns EFAULT only when the syscall exists and copied a bad pointer. Reading errno semantics correctly ("EFAULT = present, ENOSYS = absent") was the difference between "present" and "unknown". Never record a syscall as absent from a single probe failure.
3. **The old implementation's fakes were findable in minutes** (47 true-bools; `hostname("localhost")`; `$HOME` for 17 path types; 44100 Hz invented per stream). The lesson is not "the old code was bad" — it is that **fabrication is cheap, obvious on inspection, and unrecoverable for downstream trust**. Make fabrication the top lint rule for reviewers: every field in a response must trace to a host call.
4. **The brief was wrong about macOS SCM_RIGHTS.** `SCM_RIGHTS` is POSIX ancillary data, not a Linux extension; XNU implements it. The researcher's job includes correcting the brief with evidence, not following it (charter, "done" section). Recorded as §7 in the report.
5. **Count the pyramid mechanically or not at all.** I enumerated all 254 methods by ordinal and assigned tiers group-by-group so the per-OS totals reconcile (91+56+99+8 = 254 for Linux, etc.). Any pyramid whose totals don't sum to the method count is an opinion, and the brief's own acceptance test ("totals per OS") makes that checkable.
